# EPA SWMM 5.2.4 — pinned reference engine

Track B industry-parity cases compare candidate solvers to a **pinned** EPA
SWMM 5.2.4 build (version + binary SHA-256), never “SWMM” in general.

## Pinned build

- **Engine:** EPA Storm Water Management Model (SWMM)
- **Version:** 5.2.4
- **Download:** [EPA SWMM product page](https://www.epa.gov/water-research/storm-water-management-model-swmm)
  (source archive historically published as `swmm524-source.zip`)
- **Image:** `Dockerfile` in this directory (multi-stage placeholder until the
  binary is vendored)
- **Binary hash:** recorded in [`SHA256SUMS`](SHA256SUMS)

The empty-file SHA-256 in `SHA256SUMS` is an intentional **placeholder**.
Regenerate the file in CI once the real `swmm5` binary is vendored and never
hand-edit hashes to “make CI green.”

## Reference results (CI-only)

Pinned-engine **reference result Parquets are regenerated by CI**, not edited
by hand. A human PR must not commit hand-tuned `.parquet` reference outputs for
Track B cases. The workflow that runs the pinned container writes results under
the case `reference/` tree (or artifact store) and records the engine binary
hash used for that regeneration.

## Binary hash recording

1. Build or vendor `swmm5` for the target platform (see `Dockerfile`).
2. Compute `sha256sum swmm5` (or equivalent) and update `SHA256SUMS`.
3. Propagate the same hex digest into case manifests as
   `reference.binary_sha256` when promoting a case from `draft` → `candidate`.
4. CI fails if a Track B run’s engine hash does not match the pinned value.
