# Website QA/QC — 23 November 2026

A full pass over https://scott-jeffers.github.io/benchmark1d2d/ as a first-time
visitor would meet it: every page (101) on desktop and phone, light and dark
mode, every interactive tool, the model upload end to end, and an automated
accessibility scan (axe-core, WCAG 2 A/AA). Each finding below says what was
wrong, why it mattered, and what was done.

**Status key:** Fixed · Changed (a judgement call, worth a look) · Open (needs a decision or data)

## 1. Things that did not work

| # | Finding | Why it mattered | Status |
|---|---|---|---|
| 1.1 | **The upload rejected ordinary column names.** A results sheet headed `Distance (m)`, `Chainage` or `Station` was refused with "no x column", although the page promises loose column names. | The first thing most engineers would try failed. | **Fixed.** Distance, station, chainage, position, easting/northing, `depth_m`, `flow_rate` and more are read, in the browser and in the scorer (`io/results.py`). |
| 1.2 | **Unhelpful upload errors.** An unfilled template, an Excel file or a water-level column each gave a generic or misleading message. | People could not tell what to fix. | **Fixed.** Each case now says exactly what to do: fill in the empty column, save as CSV, or give depth rather than water level. |
| 1.3 | **The Publish form appeared after a failed check.** | Invited people to publish broken files. | **Fixed.** It appears only after a successful check. |
| 1.4 | **The upload mislabelled the convergence limit** as "the scheme's design order is about 0.8" (0.8 is the minimum accepted rate; the design order is 1). | Wrong technical statement. | **Fixed** on the upload page and on test pages: the design order and the minimum rate are stated separately. |
| 1.5 | **Submissions waited for a maintainer's `publish` label.** | Contradicted the automation charter ("no result waits on a person") and the goal that nobody needs to do anything. | **Changed.** Files that score without problems are published automatically, with the sender's GitHub account recorded and shown, and the site rebuilds itself. A second sender using the same software/organisation name gets their own folder and can never overwrite the first. Tested. |
| 1.6 | **The submission bot replied with PASS/FAIL.** | Verdict language the evidence protocol retired. | **Fixed.** It reports the percent difference and each measurement. |
| 1.7 | **No 404 page.** A mistyped or old link showed GitHub's generic error. | Lost visitors. | **Fixed.** A site-styled page with links to the main sections. |
| 1.8 | **Build warning:** the A1F-300 draft referenced a reference module that did not exist. | Noise in every build; would break once data arrived. | **Fixed.** `references/w5105.py` reads the table once it is committed; drafts waiting on data no longer warn. |

Checked and working: all 101 pages load in both themes with no script errors; 0 broken internal links; every GitHub file link resolves; the download kits, the three upload modes (grids, pipe networks, coupled states), grid-convergence measurement, the publish zip and the pre-filled GitHub form; the light/dark switch, the viewers and their redraws.

## 6. Open: needs your decision or data

1. **Validation evidence is thin.** One test compares models with measurements. The datasets in "In preparation" (Rubinato manhole rig model, UCLouvain model city, Toce, Malpasset, Liège, EA W5-105) are what would change that; the A12-001 rig model is the quickest.
2. **No test is frozen.** Freezing needs one recorded review of each reference (promotion rule 8). Until someone does it, every test shows "candidate".
3. **Publishing needs a free GitHub account.** That suits developers but may stop some practitioners. An email route would need a monitored address. Say if you want one.
4. **Who reviews.** The About page names you as maintainer and says the steering group is planned. Once members agree to be named, list them there.
5. **Large pages.** A1F-010's page carries ~650 KB of chart data inline; fine on broadband. Loading it on demand would help on slow links.
6. **Two new capability gaps are visible:** flow around buildings and bridges/culverts/weirs have no evidence yet. That is honest; the matrix makes it obvious.

## How this was checked

Every page captured full-length at 1366 px and 390 px; key pages also at 1100 px and 900 px, and in dark mode. Every page loaded in headless Chrome in both themes and watched for script errors; an internal link check of all `href`/`src` targets; axe-core 4 (WCAG 2 A/AA) on the main page types in both themes. The upload was driven with real files: correct four-grid results (0.033 %, convergence rate 1.00), one grid, a blank template, an unrelated CSV, a water-level sheet, an Excel file, a pipe-network sheet and a coupled-states template, then the Publish flow through to the zip and the GitHub form. The intake script was run locally on the same files with two different GitHub accounts. Python tests: 157 pass. Catalog validator: 46/46.
